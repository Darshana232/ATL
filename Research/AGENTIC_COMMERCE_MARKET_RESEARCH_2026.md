#### What ACP Solves

**Problem Statement:** How do chat-based AI agents (ChatGPT, Claude, Gemini) discover merchant products and complete purchases within conversational UI?

**ACP Solution:**
1. **Agent-Merchant Negotiation:** Agent queries merchant for products via standardized REST/GraphQL API
2. **Semantic Catalog:** Merchant returns LLM-comprehensible product schemas (name, price, stock, variants)

4. **Checkout Abstraction:** Standardized payment request (merchant-agnostic)
5. **Settlement:** Via ACP-compliant payment processor (Stripe, PayPal, etc.)

### 2.2 AP2 (Agent Payments Protocol)

**Official Spec:** [agentpaymentsprotocol.eu](https://agentpaymentsprotocol.eu/)

#### Governance & Stewardship

| Aspect | Detail |
|--------|--------|
| **Lead Developer** | Google (as of Aug 2026) |
| **Governance Transition** | Donated to FIDO Alliance (April 2026) for neutral stewardship |
| **Announced** | September 16, 2025 |
| **Partner Count** | 60+ organizations |
| **License** | Open standard (FIDO Alliance governance) |

#### What AP2 Solves

**Problem Statement:** How do payment providers cryptographically verify that an AI agent has explicit, non-repudiable authorization from a user to spend money?

**AP2 Solution:**
1. **Agent Mandate:** Digital, cryptographically signed contract specifying:
   - User ID (verified)
   - Spending limit (amount, currency)
   - Merchant/category whitelist
   - Time validity window
   - Agent identifier (unique, verifiable)

2. **Cryptographic Proof:** Before settlement, payment provider validates:
   - User's cryptographic signature on mandate
   - Timestamp (not expired)
   - Amount within limits
   - Merchant in whitelist

3. **Immutable Audit Trail:** Every authorization attempt logged with:
   - User ID, agent ID, mandate ID
   - Requested amount vs approved amount
   - Approval/rejection reason
   - Settlement confirmation + txn ID

#### Key Features (AP2 Technical Deep Dive)

**Mandate Structure (JSON Example):**
```json
{
  "mandate_id": "mandate_20260801_user12345_agent_claude",
  "user_id": "user_12345",
  "agent_id": "claude-agentic-v1-9f2e",
  "spending_limit": {
    "amount": 5000,
    "currency": "INR",
    "period": "monthly"
  },
  "allowed_merchants": [
    "bigbasket.com",
    "amazon.in",
    "flipkart.com"
  ],
  "issued_at": 1722556800,  // Aug 2, 2026 00:00:00 UTC
  "expires_at": 1753092800,  // Aug 2, 2027 00:00:00 UTC
  "payment_methods": ["upi", "card", "netbanking"],
  "user_signature": "sig_...",  // Ed25519 or similar
  "user_pubkey_id": "key_123",
  "terms_accepted": true
}
```

**Verification Flow:**
```
Payment Request (Agent → Merchant) 
→ Extract Mandate ID 
→ Query Mandate Service 
→ Verify User Signature (cryptographic validation)
→ Check: Amount ≤ Limit?
→ Check: Merchant in Whitelist?
→ Check: Time within Validity?
→ Check: Agent ID matches?
→ If ALL pass: APPROVE payment
→ If ANY fail: DENY payment + log reason
```

#### What x402 Solves

**Problem Statement:** How do software agents pay for API resources, subscriptions, or digital goods in real-time without human intervention?

**x402 Solution:**
1. **HTTP 402 Status Code:** Server responds with payment terms
2. **Cryptographic Signature:** Agent signs payment authorization (no API key exposure)
3. **Stablecoin Settlement:** Direct payment to service provider (milliseconds)
4. **Proof of Payment:** Agent receives "receipt" token + retries request with proof

#### Technical Deep Dive

**HTTP 402 Flow (Specification):**

```
Step 1: Initial Request (Agent → Server)
    GET /api/resource
    Authorization: Bearer agent_token_xyz

Step 2: Payment Required Response (Server → Agent)
    HTTP 402 Payment Required
    
    Header: x402-payment-required
    Body: {
      "amount": 0.50,
      "currency": "USDC",
      "wallet": "0x1234...abcd",
      "payload_to_sign": "hash_of_resource_request",
      "valid_until": 1722643200
    }

Step 3: Agent Prepares Payment
    - Retrieves cached balance (or top-up)
    - Signs payload with private key
    - Broadcasts to blockchain (Base, Polygon, Solana)
    - Waits for settlement confirmation (2-5 seconds typical)

Step 4: Retry with Proof (Agent → Server)
    GET /api/resource
    Authorization: Bearer agent_token_xyz
    x402-proof: {
      "txn_hash": "0xabcd...",
      "amount": 0.50,
      "timestamp": 1722560000,
      "signature": "sig_..."
    }

Step 5: Server Validates & Serves (Server → Agent)
    HTTP 200 OK
    [resource data]
    Receipt: {
      "txn_id": "0xabcd...",
      "amount": 0.50,
      "settled": true
    }
```

## India's Parallel Rollout: NPCI & UAP

### 3.1 NPCI Unified Agent Protocol (UAP) - Strategic Context

#### Why India Built Its Own Protocol

India has chosen NOT to solely adopt global standards (ACP, AP2, UCP) but instead developed a parallel, nationally-regulated framework for agentic commerce. Strategic reasons:

1. **Regulatory Sovereignty:** India wants domestic regulation of AI agents spending UPI (its national payment rail)
2. **Cultural Fit:** UPI's design (no card networks, direct bank-to-bank) aligns naturally with agent-to-agent flows
3. **Speed of Rollout:** India can move faster than global standards approval timelines
4. **Market Size:** 600M+ existing UPI users = instant TAM (total addressable market)
5. **Competitive Advantage:** First country to regulate agentic commerce nationally could attract global attention

#### Current Status (August 2026)

| Component | Status | Timeline |
|-----------|--------|----------|
| **Specification** | In development with stakeholder consultation | Draft finalized Q3 2026 |
| **Pilot Program** | Active with select merchants (Bigbasket, Vi, Zomato) | Oct 2025 - Dec 2026 |
| **Regulatory Approval** | NPCI board review in progress | Expected Q4 2026 |
| **Public Rollout** | Not announced; estimated 2027 | Likely H1 2027 |
| **Integration Complexity** | Moderate (leverages existing UPI Circle) | Merchants can prep now |

### 3.2 Technical Architecture: UPI Reserve Pay

**Foundation Layer:** NPCI's existing **UPI Reserve Pay** feature provides the infrastructure for agent authorization.

#### How UPI Reserve Pay Works (Standard UPI Feature, Pre-Agentic)

**User Flow (Without AI Agent):**
1. User opens merchant app (e.g., Bigbasket, Amazon)
2. User initiates transaction, selects "Save for later" or "Recurring"
3. User sets: Spending limit (e.g., ₹5,000), validity period (e.g., 30 days), merchant
4. User provides UPI PIN once
5. Over 30 days, user can make multiple purchases up to ₹5,000 without re-entering PIN
6. After 30 days, mandate expires; user must re-authorize

**Technical Details:**
- **NPCI Component:** UPI Circle (mandate holder) + UPI Reserve Pay (pre-authorized limit)
- **Risk Management:** Payment processor implements fraud rules (velocity checks, device fingerprinting)
- **Revocation:** User can revoke mandate anytime via app
- **Audit Trail:** Every transaction logged by NPCI

#### Agentic Extension: UPI Reserve Pay + AI Agent

**New User Flow (With AI Agent):**

```
Step 1: Initial Authorization (User → Razorpay + NPCI)
   User opens Bigbasket app
   User says: "Hey, let Claude order groceries for me this week"
   System displays:
   - Agent Name: Claude (Anthropic)
   - Permitted Actions: "Browse & purchase groceries"
   - Spending Limit: ₹5,000 total
   - Validity: 7 days
   User confirms + enters UPI PIN once

Step 2: Agent Authorization Stored
   NPCI + Razorpay create mandate:
   {
     mandate_id: "upi_reserve_pay_bigbasket_claude_202608",
     user_id: "user_12345",
     agent_id: "claude-agentic-v1-9f2e",
     merchant: "Bigbasket",
     spending_limit: 5000,
     currency: "INR",
     valid_from: 1725048000,  // Aug 2, 2026
     valid_to: 1725652800,    // Aug 9, 2026
     scope: ["browse_products", "add_to_cart", "checkout"],
     restrictions: {
       max_per_transaction: 1000,
       max_per_day: 3000,
       allowed_categories: ["groceries", "daily_essentials"],
       blacklist_items: ["alcohol", "tobacco"]  // Example
     }
   }

Step 3: Agent Operates Autonomously (Agent → Razorpay → Merchant)
   User: "Find me organic vegetables under ₹500 that can reach tomorrow"
   
   Claude Agent:
   - Queries Bigbasket API (via Razorpay MCP server)
   - Filters: organic=true, price≤500, delivery_tomorrow=true
   - Validates against mandate (amount ≤ 1000, category "groceries")
   - Builds cart: tomatoes (₹120), spinach (₹80), carrots (₹200) = ₹400 total
   - Requests payment from Razorpay

Step 4: Payment Execution
   Razorpay:
   - Validates agent mandate against stored authorization
   - Checks: amount (₹400 < ₹1000 limit), category ("groceries" ✓), time window (valid)
   - Creates UPI Reserve Pay transaction request
   - NPCI processes (no PIN required, within mandate)
   - Razorpay receives settlement confirmation

Step 5: Completion
   Agent confirms to user: "Order placed! Organic vegetables (₹400) arriving tomorrow 7-9 AM"
   Audit log entry created with full decision trail
```

- Digital contract between user + agent (signed by both)
- Specifies: spending limits, merchant list, transaction categories, time window
- Stored at NPCI's mandate service (redundant, highly available)
- Revocable anytime by user

**Transaction Authorization:**
- Before payment, system verifies:
  - Mandate exists and is current
  - Amount ≤ per-transaction limit
  - Daily spending ≤ daily cap
  - Category in whitelist
  - Merchant in approved list
  - Transaction time within mandate window

**Audit & Dispute Resolution:**
- Every agent-initiated transaction logged:
  - Agent ID, mandate ID, transaction ID
  - User ID, merchant ID
  - Amount, category, timestamp
  - Authorization decision (approved/rejected) + reason
  - Settlement status
- Logs stored for 7 years (Indian financial regulation)
- Used for dispute resolution (chargeback / refund requests)

```python
class AgentState(TypedDict):

def supervisor_agent(state: AgentState) -> AgentState:
    """
    Routes user intent to specialized agents
    Aggregates results and decides on payment
    """
    
    # Step 1: Discovery Agent
    discovery = discovery_agent(state["user_intent"])
    state["discovered_products"] = discovery["products"]
    
    # Step 2: Selection Agent
    selection = selection_agent(
        intent=state["user_intent"],
        products=state["discovered_products"]
    )
    state["selected_cart"] = selection["cart"]
    state["total_price"] = selection["total_amount"]
    
    # Step 3: Pricing Agent
    pricing = pricing_agent(
        cart=state["selected_cart"],
        merchant_id=selection["merchant_id"]
    )
    state["total_price"] = pricing["final_amount"]
    state["applied_discounts"] = pricing["discounts"]
    
    # Step 4: Guardrail Validator
    validation = guardrail_validator(
        amount=state["total_price"],
        user_id=state["user_id"],
        mandate_id=state["mandate_id"]
    )
    if validation["status"] == "APPROVED":
        state["approval_status"] = "READY_FOR_PAYMENT"
    else:
        state["error"] = validation["reason"]
        state["approval_status"] = "REQUIRES_HUMAN_APPROVAL"
    
    # Step 5: Log Decision
    state["audit_log"].append({

    })
```

```python
def validate_upi_reserve_pay_mandate(
    user_id: str,
    agent_id: str,
    merchant_id: str,
    amount_inr: float
) -> AuthorizationResult:
    
    # Step 1: Retrieve mandate from NPCI
    mandate = npci_reserve_pay_service.get_mandate(
        mandate_id=f"upi_{user_id}_{agent_id}_{merchant_id}"
    )
    
    if not mandate:
        return AuthorizationResult(
            status="DENIED",
            reason="No mandate found"
        )
    
    # Step 2: Check expiration
    if mandate.valid_to < current_timestamp():
        return AuthorizationResult(
            status="DENIED",
            reason="Mandate expired"
        )
    
    # Step 3: Check spending limits
    daily_spent = get_daily_spending(user_id, mandate.valid_from)
    if daily_spent + amount_inr > mandate.daily_limit:
        return AuthorizationResult(
            status="DENIED",
            reason=f"Daily limit exceeded (limit: {mandate.daily_limit}, already spent: {daily_spent})"
        )
    
    if amount_inr > mandate.per_transaction_limit:
        return AuthorizationResult(
            status="DENIED",
            reason=f"Transaction exceeds per-txn limit ({amount_inr} > {mandate.per_transaction_limit})"
        )
    
    # Step 4: Check merchant allowlist
    if merchant_id not in mandate.allowed_merchants:
        return AuthorizationResult(
            status="DENIED",
            reason=f"Merchant {merchant_id} not in whitelist"
        )
    
    # Step 5: Check category restrictions (if applicable)
    for item in cart:
        if item.category not in mandate.allowed_categories:
            return AuthorizationResult(
                status="DENIED",
                reason=f"Category '{item.category}' not permitted"
            )
        if item.category in mandate.blacklisted_categories:
            return AuthorizationResult(
                status="DENIED",
                reason=f"Category '{item.category}' is blacklisted"
            )
    
    # Step 6: All checks passed
    return AuthorizationResult(
        status="APPROVED",
        mandate_id=mandate.id,
        remaining_daily_limit=mandate.daily_limit - (daily_spent + amount_inr)
    )

def execute_payment(
    authorization: AuthorizationResult,
    merchant_id: str,
    amount_inr: float,
    cart_id: str,
    user_id: str
) -> PaymentResult:
    
    # Step 1: Create Razorpay payment link (test-mode)

        # Step 4: Log to audit trail
        audit_log.append({
            timestamp: current_timestamp(),
            event: "payment_success",
            payment_id: payment.id,
            amount: amount_inr,
            mandate_id: authorization.mandate_id,

            user_id: user_id,
            merchant_id: merchant_id,

        })
        
        return PaymentResult(
```

## Security, Guardrails & Regulatory Framework

### 6.1 The Mandatory Guardrails Bar (2026 Standard)

Every money action must be: **Explainable** | **Bounded** | **Gated**

#### 1. Hard Spending Limits

**Per-Transaction Cap:**
- Example: Agent cannot authorize > ₹1,000 per transaction
- Enforcement: Payment provider validates before settlement
- Escalation: Request > ₹1,000 triggers human approval (user must confirm via app)

**Daily Cumulative Cap:**
- Example: Agent cannot spend > ₹5,000 total per day
- Enforcement: Payment provider checks daily total before settlement
- Reset: Midnight UTC (or per merchant's timezone)

**Implementation Example:**
```python
def validate_spending_limit(
    amount: float,
    user_id: str,
    mandate_id: str
) -> ValidationResult:
    mandate = get_mandate(mandate_id)
    daily_spent = get_daily_spending(user_id, date.today())
    
    # Check per-transaction
    if amount > mandate.per_transaction_limit:
        return ValidationResult(
            status="DENIED",
            reason=f"Amount ₹{amount} exceeds per-txn limit ₹{mandate.per_transaction_limit}"
        )
    
    # Check daily cumulative
    if daily_spent + amount > mandate.daily_limit:
        remaining = mandate.daily_limit - daily_spent
        return ValidationResult(
            status="DENIED",
            reason=f"Daily limit exceeded; remaining: ₹{remaining}"
        )
    
    return ValidationResult(status="APPROVED")
```

#### 2. Velocity Caps

**Max Transactions Per Hour:**
- Example: Max 5 transactions/hour to prevent runaway loops
- Detection: Count settled transactions in past 60 minutes
- Escalation: 6th transaction → denied, user notified

**Max Transactions Per Day:**
- Example: Max 20 transactions/day
- Reset: Midnight

**Implementation:**

```python
def check_velocity(user_id: str, mandate_id: str) -> VelocityCheckResult:
```

#### 3. Allowlists (Whitelisting)

**Merchant Whitelist:**
- User specifies: "Agent can only buy from Bigbasket and Amazon"
- Enforcement: Payment denied if merchant not in list
- Management: User can add/remove via app anytime

**Category Whitelist:**
- User specifies: "Agent can buy groceries, NOT alcohol or tobacco"
- Enforcement: Categorized by merchant system
- Flexibility: Granular (product-level) or broad (category-level)

**Implementation:**
```python
def check_allowlist(
    merchant_id: str,
    items: List[Product],
    mandate_id: str

            )
```

#### 4. Tiered Approval Workflows

**Tier 1: Automatic (< ₹500)**
- User has pre-approved; no additional confirmation needed
- Payment auto-settles
- User receives post-transaction notification

**Tier 2: Notification (₹500-₹2,000)**
- User receives soft push: "Agent bought [item] for ₹[amount]"
- User can retroactively block within 10 seconds
- If blocked: Payment reverses (test-mode) or refund issued (production)
- Default: Approve after 30 seconds if no response

**Tier 3: Human Approval (> ₹2,000)**
- Transaction blocks, user receives hard push + app modal
- User MUST tap "Approve" or "Deny"
- Timeout: 5 minutes; auto-deny if no response
- Requires biometric or PIN on production

**Implementation:**
```python
def determine_approval_tier(
    amount: float,
    mandate: Mandate
) -> ApprovalTier:
    if amount < mandate.auto_approve_threshold:  // Default: ₹500
        return ApprovalTier.AUTOMATIC
    elif amount < mandate.notification_threshold:  // Default: ₹2,000
        return ApprovalTier.NOTIFICATION
    else:
        return ApprovalTier.HUMAN_APPROVAL

async def execute_approval_workflow(
    approval_tier: ApprovalTier,
    user_id: str,
    amount: float,
    payment_id: str,
    mandate_id: str
):
    if approval_tier == ApprovalTier.AUTOMATIC:
        # Auto-approve, proceed to payment
        return await execute_payment(payment_id)
    
    elif approval_tier == ApprovalTier.NOTIFICATION:
        # Send soft notification, wait 30 seconds, auto-approve if no response
        send_notification(
            user_id=user_id,
            message=f"Agent spent ₹{amount}",
            action_required=False
        )
        
        user_response = await wait_for_response(
            user_id=user_id,
            timeout_seconds=30
        )
        
        if user_response == "BLOCK":
            return await reverse_payment(payment_id)
        else:
            return await execute_payment(payment_id)
    
    elif approval_tier == ApprovalTier.HUMAN_APPROVAL:
        # Block payment, require explicit approval
        send_approval_modal(
            user_id=user_id,
            message=f"Agent requests ₹{amount} approval",
            action_required=True
        )
        
        user_response = await wait_for_response(
            user_id=user_id,
            timeout_seconds=300
        )
        
        if user_response == "APPROVE":
            return await execute_payment(payment_id)
        else:
            return await cancel_payment(payment_id)
```

```python
def execute_with_graceful_fallback(operation, context):
    try:
        return operation()
    except RecoverableError as e:
        error_type = type(e).__name__
        
        # Log the error
        audit_log.append({
            timestamp: now(),
            event: f"error_{error_type.lower()}",
            severity: "warning",
            error_details: str(e),
```

```python
from langgraph.graph import StateGraph, START, END
from langgraph.types import StreamWriter

class CommerceState(TypedDict):
    user_intent: str
    discovered_products: List[Product]
    selected_cart: List[CartItem]
    total_price: float
    discounts_applied: List[Discount]
    authorization_status: str  # "APPROVED" | "DENIED"
    error_message: str

# Define sub-agents
discovery_agent = create_agent("discovery", model=claude, tools=[search_tool, details_tool])
selection_agent = create_agent("selection", model=claude, tools=[add_to_cart_tool])
pricing_agent = create_agent("pricing", model=claude, tools=[discount_tool])
auth_agent = create_agent("auth", model=claude, tools=[mandate_validator, guardrail_checker])

# Define graph
graph_builder = StateGraph(CommerceState)

def supervisor(state: CommerceState) -> CommerceState:
    """Routes to sub-agents and aggregates results"""
    
    # Step 1: Discovery
    discovery_result = discovery_agent.invoke({
        "user_intent": state["user_intent"],
        "merchant_id": extract_merchant(state["user_intent"])
    })
    state["discovered_products"] = discovery_result["products"]
    
    # Step 2: Selection
    selection_result = selection_agent.invoke({
        "intent": state["user_intent"],
        "products": state["discovered_products"]
    })
    state["selected_cart"] = selection_result["cart"]
    state["total_price"] = selection_result["total"]
    
    # Step 3: Pricing
    pricing_result = pricing_agent.invoke({
        "cart": state["selected_cart"],
        "user_id": state["user_id"],
        "merchant_id": discovery_result["merchant_id"]
    })
    state["total_price"] = pricing_result["final_amount"]
    state["discounts_applied"] = pricing_result["discounts"]

        "amount": state["total_price"],

        "cart": state["selected_cart"]
    })
    state["authorization_status"] = auth_result["status"]
    if auth_result["status"] == "DENIED":
        state["error_message"] = auth_result["reason"]
    
    # Step 5: Log
    state["audit_trail"].append({
        timestamp: now(),
        event: "supervisor_decision",
        final_amount: state["total_price"],
        auth_status: state["authorization_status"]
    })
    
    return state

graph_builder.add_edge("supervisor", END)

# Compile

# Execute
result = graph.invoke({
    "user_intent": "Find me organic vegetables under ₹500",
    "user_id": "user_12345",
    "mandate_id": "mandate_bigbasket_claude_20260801",
    "audit_trail": []
})

print(result["audit_trail"])  // Full decision trail
```

#### 2. Agent Hallucination at Scale

**The Problem:**
- Agents recommend products that don't exist in catalog
- Agents misremember prices or availability
- Agent confidence is uncalibrated (confident in wrong recommendations)

**Example Hallucination:**
```
User: "Find me running shoes under ₹2,000"
Agent: "I found these great Nike Air Zoom Pegasus (₹1,800), 
        Adidas Ultraboost (₹1,900), and Puma RS-X (₹1,500)"

Reality: Puma RS-X isn't in Bigbasket inventory 
(Agent generated fake product from training data)

User: Places order, payment goes through
Later: Agent (or merchant) notifies user "Item not available"
→ User frustrated, refund required
```

**Market Opportunity:**
- **Hallucination Detection Engine:** Real-time verification that agent's product recommendations exist + match stated specs
- **Agent Grounding Service:** Embed verification into agent loop (before payment)
- **Confidence Calibration:** ML model that assigns confidence scores to agent recommendations
- **Fraud Detection:** Detect agents repeatedly recommending non-existent items

**Tech Stack:**
- Semantic similarity (embed agent recommendation → embed actual product → cosine similarity)
- Knowledge graph (merchant catalog as structured data)
- Behavioral analytics (track agent accuracy over time)

**Estimated TAM:**
- Cost per merchant: ₹10K-50K/month (recurring)
- Merchants needing this: 70%+ of large merchants
- **Market size:** ₹500Cr annually (India) + ₹2,000Cr (global)

#### 3. Enterprise Procurement Agents (B2B)

**The Problem:**
- All live platforms focus on B2C (individual consumers)
- B2B has complex approval workflows (3+ stakeholders)
- Agentic commerce untapped in enterprise procurement

**Example B2B Use Case:**

```
  Step 3: Sends to Budget Owner for approval
  Step 4: Sends to Procurement Manager for vendor verification
  Step 5: Sends to CEO for final sign-off (if > ₹50 lakh threshold)
  Step 6: Once all approve → execute purchase order
  Step 7: Track fulfillment + delivery + invoicing
```

**Market Opportunity:**
- **Enterprise Procurement Agent:** Multi-stakeholder approval workflows
- **Vendor Compliance Checking:** Auto-verify vendor meets company standards
- **Contract Integration:** Agents fetch pricing from negotiated contracts
- **Spend Analytics:** Agents optimize for cost + delivery time tradeoff
- **Compliance Audit Trail:** Mandatory for enterprise purchasing

**Market Size (India):**
- Enterprise spend via procurement agents: ~$50-100B annually (if adopted)
- Platform take rate: 0.5-1% = $250M - $1B
- **Razorpay addressable:** Top 10K companies in India = ₹50Cr - ₹200Cr

**Competition:**
